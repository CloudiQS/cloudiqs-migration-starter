# Evidence rules

- A claim from guidance quotes the source text and names file plus heading. Open the page before quoting; never paraphrase into a quote.
- Labels: `[CUSTOMER]` said by the customer; `[DISCOVERY]` from discovery data; `[SSB-DIRECT]` guidance as written; `[SSB-ADAPTED]` nearest guidance applied to an unlisted case, naming what was borrowed and what is missing; `[PARTNER-JUDGMENT]` CloudiQS judgement; `[OPEN]` unresolved, with owner and next action.
- Evidence types never blend: `live` (ran in this engagement's account), `reference` (supplied results from elsewhere), `simulation` (lab only). Write the type on every row.
- An empty proof field means the task is not complete. `NOT RUN` and `OPEN` are honest results; use them.
- A disposition (owner plus action) completes the record but never turns `OPEN` into `PASS`.
- Never store or print secret values. Env files hold identifiers and ARNs only.
- Before trusting a criterion, check it can be measured against the real schema, metric or log.
